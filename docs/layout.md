# 目录约定

这一篇讲站点的目录模型：项目根、三个根（页面/模板/资源）与产物映射。

**项目根**是所有相对路径的基准：有 `.goweb.yml` 时就是它所在目录（可从运行目录向上找到），没有配置文件时就是运行目录。三个根彼此独立：

| 根 | flag / 配置键 | 默认 | 作用 |
| --- | --- | --- | --- |
| 页面根 | `-d/--dir` / `dir` | `.` | 递归出现的 `*.html` 都是页面；页面 URL 与产物路径以它为基准 |
| 模板根 | `-t/--template` / `template` | `templates` | 局部模板与 `data.json`；内部 html 不产出页面、也不能被访问；**不受 `--dir` 影响** |
| 资源根 | `--assets` / `assets` | `.` | 其余文件按它映射到产物、`serve` 时直接对外提供 |

> ⚠️ **与 v0.1.x 的差别**：早期版本的 `--template` 是「相对页面目录的目录名」，现在它是「相对项目根的路径」。`-d .` 时行为不变；`-d site -t templates` 的旧语义（`site/templates`）改为项目根下的 `templates`，需要模板跟着页面目录走时请显式写 `-t site/templates`。

**产物映射**（保证 URL 与产物路径始终一致，页面里的相对引用才对得上）：

- 页面 → `<out>/<相对页面根的路径>`
- 资源 → 位于**页面根内**按页面根、否则按资源根
- 资源遍历范围是**页面根 ∪ 资源根**：默认布局下两者都是项目根，整棵树只走一遍；两棵根互不包含时（例如 `--dir pages --assets assets`）页面根里的非 html 文件同样按页面根进产物
- 两个来源映射到同一产物路径 → **直接报错**并列出两个来源（作为**一条**问题列出，附两个来源路径）

**软链接**（`serve` 与 `gen` 策略一致）：

- 指向三个根内普通文件的符号链接：`serve` 直出、`gen` 按内容拷贝。
- 指向目录、站点根之外或已失效的链接：`serve` 视为 404；`gen` 跳过并打印告警，不因一个无关坏链接让整次生成失败。
- 产物目录本身是符号链接：`gen` 直接拒绝（`clean` 会顺着链接删掉目标目录里的内容）。

**模板根不能覆盖页面根/资源根**：模板根等于页面根、或位于它们的祖先位置时，页面发现与资源发布会被整体清空（产物是空的却照样成功），因此加载期直接报错。默认布局（模板根在页面根与资源根之内）不受影响。

**忽略规则**（项目根的 `.gitignore` + 配置里的 `ignore`，同语法）**只作用于 `gen`**：

- 被忽略的文件不进产物，但 `serve` 仍然能看到（方便本地预览草稿）；代价是本地存在的 URL 线上可能 404。
- 语法子集：`*`、`?`、`**`、`[...]`、`!` 反选、前导 `/` 锚定、结尾 `/` 目录限定、`#` 注释；**不支持**嵌套 `.gitignore`、`core.excludesFile` 与反斜杠转义（有测试用真实 `git check-ignore` 对拍）。
- 若页面引用了被忽略的资源，`gen` 会**直接报错**（产物里不会有它，静默断链更糟）；用 `--fingerprint=false` 关掉自动改写时则不会检查。

**产物目录的清理边界**：`--out` 落在页面根/资源根内部时（例如误写 `--out static`），`clean` 会清空该目录里原有的源码文件；`gen` 在清空前会打印告警，但仍会执行。产物目录是符号链接时直接报错，不会删除任何东西。

**始终忽略**（`serve` 与 `gen` 都生效）：以 `.` 开头的文件/目录、`node_modules/`、**当前 `--out` 指定的产物目录**、模板根。模板根与产物目录内的文件不会对外提供（访问返回 404）。

> ⚠️ **只排除「当前」产物目录**：换过产物目录后（例如先用默认 `dist/`，后来 `--out public`），旧的 `dist/` 仍是资源根里的普通目录，会被拷进新产物。约定做法是把产物目录写进 `.gitignore` 或配置里的 `ignore`：
>
> ```gitignore
> dist/
> ```
>
> 这条边界有测试锁定（`TestGenCommandOutDirBoundary`）：连跑两次同名产物不会自我嵌套，而旧产物目录确实会被当资源拷贝。
