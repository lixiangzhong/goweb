# 设计取舍与边界

这一篇讲关键设计取舍，以及当前明确「不做」的范围。

## 设计取舍

- **开发服务器等效 `try_files`**：解析顺序就是 `try_files $uri $uri.html $uri/index.html`，零重定向、不做 URL 重写；本地结果与用同一行配置部署的线上结果逐条一致（`/about` 能开、`/about/` 404 都一致），站内链接写 `/about.html` 最稳。
- **单一 `html/template` 命名空间**：所有页面与局部模板一起解析，`{{template "x" .}}` 全局可用；代价是不同文件里同名 `define` 会互相覆盖。
- **不做缺键校验**：JSON 直接解成 map 当模板数据，缺键渲染成空串而不是报错，实现最简且不会误伤 `range`/`with` 内部取值；代价是拼错键名会静默留白。
- **浏览器热重载是可选的注入**：`serve` 默认注入刷新脚本，`gen` 产物永远干净；用 `--livereload=false` 可让开发时看到的 HTML 与线上完全一致。
- **渲染失败即失败**：宁可让 `gen` 报错退出，也不产出一个缺页面的半成品静态站。
- **用 cobra 而不是标准库 `flag`**：换来统一的 `--help`/`--version`/shell 补全与更清晰的子命令结构，代价是多两个间接依赖（pflag、mousetrap）；公共参数（`--dir`/`--template`/`--assets`/`--config`）做成 persistent flag，保证 `goweb --dir pages gen` 不会被静默忽略。
- **三个根彼此独立 + 项目根**：页面、模板、资源各自可配，都相对项目根（`.goweb.yml` 所在目录，没有则运行目录）。代价是概念比单根多一层，好处是 `pages/ + templates/ + static/` 这类布局不用把模板塞进页面目录；早期 `--template` 相对页面目录的语义是破坏性变更（`-d .` 时行为不变）。
- **忽略规则只作用于 `gen`**：被忽略的文件本地仍可见（方便预览草稿），代价是本地存在的 URL 线上可能 404；相比「两边一致」的严格模式，这是用户明确选择的行为。引用被忽略的资源时 `gen` 会报错，避免产物里留断链。
- **自动开浏览器是非关键副作用**：`serve` 默认打开系统浏览器（`--open=false` 关闭），因为「改完立刻看到」是它的主要使用方式；但打开动作失败（CI、SSH、无桌面环境）**只记一条日志**，绝不中断服务——附属动作不应该成为新的失败源。用 `GOWEB_OPEN_COMMAND` 可覆盖平台命令（WSL 的 `wslview` 等）。

- **压缩只作用于产物，且不做改名**：`gen`/`build` 默认压缩（`--minify=false` 关闭），`serve` 永远不压缩，开发时保持可读、可断点调试；JS 关闭局部变量改名（KeepVarNames），因为「minify」的定位是去空白与注释，而不是 uglify 式的改名压缩——工具的第一原则是不改坏用户的站点。代价是体积比 terser 之类的方案大一些。

- **默认只监听本机**：开发服务器默认 `127.0.0.1:8080`。它会把站点目录里所有非隐藏文件对外提供，绑到通配地址等于把整个工作目录暴露给局域网；要开放必须显式 `--addr :8080`。

- **文件监听失败不拖垮服务**：fsnotify 初始化失败或补挂监听出错只告警并关闭热重载，`serve` 照常提供页面——热重载是附属功能，不该成为启动的前置条件。

- **软链接统一策略**：`serve` 与 `gen` 都只接受「指向三个根内普通文件的符号链接」；指向目录、站点根之外或已失效的链接一律视为不存在（`serve` 404、`gen` 跳过并告警），产物目录本身是符号链接则直接拒绝（`clean` 会顺着链接删掉目标）。

- **端口只在「没指定」时避让**：开发时 8080 常被别的项目占着，因此默认端口被占用会自动递增（`--addr` 未显式给出时）；一旦显式指定端口就保持快速失败——「我说了 8080 却跑在 8081」比启动失败更让人困惑，而想固定端口的人本来就会显式写 `--addr`。

- **忽略自己的日志文件**：`serve` 会跳过 stdout/stderr 指向的文件（`goweb serve > site/x.log` 的安全网）。判据是 `os.SameFile`，终端与管道天然不会命中，因此不引入额外的配置项。

- **`check` 复用 `gen` 的同一条管道**：校验模式（`Generate` 的 `Check`）与生成共用同一套映射、冲突登记与跳过规则，只在「是否落盘」和「记录问题 vs 立即失败」两处分叉；代价是 `Generate` 多了一个模式参数，好处是不会出现第二套真相源——校验说没问题、生成却失败。链接检查刻意在「产物视角」判定（目标会进产物且 URL 与产物路径一致），因此能抓出「本地能开、线上没有」的链接。
- **日志颜色只在终端生效**：非 2xx 的 status 在终端里按 3xx 青／4xx 黄／5xx 红上色，判据是输出流是否字符设备、并遵循 `NO_COLOR`；重定向到文件或管道时输出纯文本，避免日志里混入转义序列。颜色在「写完的整行文本」上替换而不是塞进 slog 字段——slog 会把含控制字符的值转义成更难读的形式。
- **`init` 生成的配置等于默认值**：除 `addr` 外 13 个键都写出当前默认值，因此文件出现不改变任何行为（`addr` 只以注释列出：显式写它会被视为「我就要这个端口」，从而关掉端口自动递增）。键集合由测试与 `fileConfig` 双向对齐，避免新增配置项时模板静默漏掉。

## 目前不做

CSS 热替换（改样式仍整页刷新）、自定义 404 页面、多语言（i18n）、资源文件名带哈希（目前用 `?v=<内容哈希>` 查询串）、每页独立数据（只提供站点级 `data.json`）。

页面、模板、`data.json` 与静态资源变更后都会自动重载，并通过热重载让浏览器自动刷新。
